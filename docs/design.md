# 設計の理由

操作方法は [README](../README.md)、書式は [Resource 仕様](resource.md)、配布の手順は [公開手順](publishing.md) を参照。

## 課題ごとにバージョンを管理する

課題ごとにバージョンを定義することができ、新しバージョンが発行されるとなんらかの方法でアーティファクトが生成される。
イメージをlatestタグなどのタグで指定していた場合、その時点でのタグ参照先のdigestで置き換える。
具体的仕様はまだ決まっていない。

## その他

入力は呼び出し中に変更しないことを前提とする。
hardlink は通常ファイルとして読み、inode の共有まではチェックしない。
